FEES101 REDESIGN PROGRAM
v1 · dev branch · 45 surfaces

Rebuild the instrument, not the paint.

Fees101 currently reads like a dashboard template: rounded cards, a mint accent, a colour-coded badge for every state. The rework replaces that with a single hard grid, one ink-and-red palette, type that carries hierarchy instead of containers, and motion that behaves like machined hardware. Every one of the 45 surfaces below is rebuilt — nothing carries over.

01 — DIRECTION

Hardware, not software

No cards, no shadows, no radius. Surfaces are divided by 2px rules and precise gutters. Weight and position do the organising — the interface should feel milled.

Money as measurement

Figures set in tabular numerals at display sizes, aligned on the decimal, never inside a pill. A balance is a readout, not a metric card.

One accent, earned

Red means "this needs you" — overdue, unsent, rejected, destructive. Everything else is ink on paper. The current five-colour status rainbow is retired entirely.

Two grounds

Paper (#f3f2f2) for operating work — rosters, invoices, settings. Ink for the instrument surfaces — collections, analytics, the cycle close. Switching ground tells you which mode you're in.

Deliberate motion

Slow-out easing, short travel, no bounce, no spinners. Rules draw, numerals count, panels slide on one axis. Nothing fades in place for decoration.

Fewer, larger surfaces

21 nav destinations collapse to 7 workspaces with modes. A bursar should never wonder whether the thing they want is under Fees, Invoices or Settings.

03 — INFORMATION ARCHITECTURE

21 destinations become 7 workspaces.

Each workspace owns one job and holds its modes as in-page tabs, so navigation depth drops from three levels to two and the sidebar stops being a directory.

WorkspaceAbsorbsWhy
TodayDashboard, Recent activity, admin notificationsOne surface answering "what needs me this morning" — outstanding money, unsent invoices, pending approvals, the live stream. Replaces the KPI grid.

05 — MOTION SPECIFICATION

Four durations, two curves, one axis at a time.

TokenValueUsed by
tick120msHover tints, focus ring, checkbox, sort-arrow flip
move200msTab underline travel, row expand, tag swap
enter320msDrawer and panel slide, mode change, content wipe (12px up)
settle560msRule draw on section mount, numeral count-up, job progress fill
ease-outcubic-bezier(.2,0,0,1)Everything entering or settling
ease-incubic-bezier(.4,0,1,1)Everything leaving

Rule draw

Section dividers scale from the left on first paint. The system's signature move — it makes the grid assemble itself rather than appear.

Numeral count

Every displayed total counts from zero once, in tabular figures so no digit shifts. Never on re-render, only on arrival.

No spinners

Loading is a 2px rule sweeping its own track. Jobs fill it proportionally; indeterminate work sweeps. Nothing spins anywhere in the product.

Single-axis panels

Drawers come from the right, sheets from the bottom, modes wipe up. A surface never moves on two axes or scales.

Table choreography

Sort and filter reorder rows with a 200ms position transition, capped at 24 visible rows so the page never churns.

Reduced motion

Under prefers-reduced-motion every token collapses to 0ms and count-ups render final values. Layout never depends on animation.

06 — SIGNALS: ONE NOTIFICATION LANGUAGE

Today the product speaks in three unrelated voices: an admin banner at the top of every page, a live job-progress chip, and ad-hoc toasts. They become one system with four registers, each with a fixed position and a fixed lifetime.

RegisterPositionLifetimeCarries
ConfirmBottom-left, ruled slab4s, dismissible"18 invoices sent." Result of an action you just took.
ProgressDocked strip under the headerUntil done or backgroundedJob label, filling rule, count, cancel. Survives reload and tab change.
AttentionIn-context, above the affected regionUntil resolvedRed-accented: unsent invoices, failed job, provider credentials invalid.
RecordStream drawer, right edgePersistent historyThe activity feed, opened from anywhere — no longer its own page.

08 — WHAT IS DECIDED, AND WHAT IS STILL OPEN

The system is settled. The remaining work is depth, not direction.

Every decision that shapes other decisions has been made and is visible somewhere in this project: the mark, the palette and its rules, the type scale, the two grounds, the motion tokens, the seven-workspace structure, the Signals language, and the voice of what parents receive. What is left is a small number of deep screens and the artefacts nobody sees until something goes wrong.

Decided — do not revisit

  • Mark A, the stack — rule is a separate element, so the accent can change without redrawing it
  • Archivo 400/600/800, tabular numerals on every figure
  • Signal red for brand and structure, green for money received, ochre for what needs a human
  • Paper for operating, ink for the ledger and analytics
  • Four motion durations, two curves, no spinners anywhere
  • 21 permission destinations collapsed to 7 workspaces with in-page modes
  • Option B subject lines — child first, then the figure

Still open — real work

  • Student fees tab — opt-in management, exemptions and adjustments; the largest unread component in the repo
  • Comparisons & rates — head-to-head of up to five periods with the metric toggle
  • Receipt PDF — pairs with the invoice PDF
  • Staff invite email — the one message that goes to staff
  • Narrow-role index — the landing surface for a role with one destination

Deliberately dropped

  • Payment simulator — internal test surface, never seen by a school
  • Parent-facing app — messages only, as decided at the start
  • Before/after panels on surfaces not yet rebuilt — the compare control disables itself rather than lying
  • Mobile-first layouts — desktop-first with reflow, as decided

What to give it

Open the design file for the surface being built and keep it beside the editor — the values are all inline, so they read straight off the markup. github.md in this project records which repo files each screen was designed from.

What not to let it do

Do not let it change queries, server actions or RLS policies — this is a UI rework and the data layer is already correct. If a screen seems to need new data, that is a design question to bring back here first.

How to know a step is done

No rounded corners, no shadows, no mint, no Manrope, no coloured pills, no spinners. Every figure tabular. Green only where money arrived. If any of those appear, the step is not finished.
